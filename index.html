02

项目经验

说明：因项目涉及敏感业务信息，以下内容已做脱敏处理，仅保留技术层面描述。

项目概述

平台基于 Spring Cloud Alibaba 微服务架构，按业务域拆分，本人核心负责配置管理、数据实战、对外服务三大子系统架构设计与落地，主导核心模块架构重构。

Spring Boot Spring Cloud Alibaba MySQL Redis Kafka Dify SM2/SM4 国密 SkyWalking Docker Compose

配置管理子系统 元数据驱动架构重构

背景

新业务模型接入依赖硬编码开发，周期 5~10 天；无版本管理、无法灰度，跨服务数据频繁不一致。

主要工作

  • 设计元数据驱动架构，前端可视化配置业务模型，审批通过后自动执行动态 DDL 创建物理表，支持扩展字段，消除重复硬编码开发
  • 实现多版本数据物理隔离，配置变更自动备份历史表，通过版本号动态路由查询，支持变更全链路追踪
  • 基于 Kafka 构建跨服务数据同步通道，通过生产者重试、失败消息持久化、定时补偿实现至少一次投递；下游消费完成回调确认，形成「生产→消费→确认→补偿」一致性闭环
  • 支持按用户维度灰度放量，历史数据一次性全量同步，增量数据采用平台定时抽取，配合每日数据对账

项目成果

新业务模型接入无需开发人员参与，通过界面配置即可完成；1 个月完成 50+ 张数据表迁移，实现 0 数据丢失、0 业务中断，彻底解决跨服务模型不一致故障。

数据实战子系统 14s → 1s 左右

背景

核心表单数据量达千万级，历史设计缺陷导致列表查询平均耗时 14s；数据权限硬编码，变更必须版本发版；业务需要引入 AI 实现自然语言自助查询。

主要工作

  • 千万级查询深度优化：雪花算法 BIGINT 主键替换 UUID、优化时间字段索引；批量插入替代循环单条写入，移除低效同步触发器；规避多字段 OR 模糊查询，大字段按需异步加载；按时间维度构建冗余表，实现查询自动路由，数据扫描量降低 70%+
  • 动态权限管控表达式引擎：权限规则以表达式形式配置化存储，运行时通过反射机制动态获取因子属性值并解析计算，实现按钮级/字段级权限控制；规则变更实时生效，无需发版
  • 基于 Dify 编排 AI 工作流，通过 iframe 嵌入业务系统；采用参数化查询、访问白名单、敏感字段自动脱敏，实现安全可控的自然语言数据查询

项目成果

核心列表查询耗时从 14s 优化至 1s 左右；权限变更从天级别发版缩短至秒级生效，释放大量研发人力，规避权限配置不当引发的数据泄露风险。

对外服务子系统 10s → 1~2s

背景

平台统一对外 API 出入口，承载跨机构敏感数据交互，缺少标准化安全防护；原有串行校验逻辑接口平均响应 10s，高并发场景频繁超时。

主要工作

  • 落地数字信封混合加密方案：业务数据 SM4 对称加密，动态对称密钥通过 SM2 非对称加密传输；基于 SM2 实现请求签名验签；统一拦截器实现全接口无感加解密
  • 将串行校验改造为 CompletableFuture 并行执行；校验能力独立拆分为微服务，依托 Nacos 实现水平扩容；搭建 Redis 缓存 + 布隆过滤器架构，配套策略解决缓存穿透/击穿/雪崩
  • 通过 Sentinel 配置 QPS 限流、异常比例熔断降级；统一拦截加解密失败、验签失败、调用超时等异常，实现结构化日志、自动告警，形成问题闭环

项目成果

达到金融级接口安全标准，顺利通过年度安全审计；接口平均响应优化至 1~2s，缓存命中场景耗时低于 1s；连续 3 个月无服务不可用事故。
