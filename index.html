项目经验

说明：因项目涉及敏感业务信息，以下内容已做脱敏处理，仅保留技术层面描述。

技术栈

Bootstrap 自研低代码平台 Spring Boot MySQL Redis Kafka Dify

高并发查询性能优化 14s → 500ms

问题背景

业务系统核心查询表数据总量超 1000 万，日均增量 3-4 万条。业务需要支持多字段任意子串模糊匹配组合查询，且要求实时返回结果。优化前页面查询耗时约 14 秒，高峰期数据库连接池经常耗尽。

解决思路

  • 索引策略：ngram 分词器替代 LIKE 模糊匹配
  • 扫描范围控制：时间范围限制 + 分区表
  • 写入优化：批量入库，降低 IO 和索引更新压力
  • 异步化解耦：同步触发器改为异步消息队列

优化效果

14 秒 → 500ms，降低约 60%

高并发标签命中校验 10s → 800ms

问题背景

对外接口需校验请求数据是否命中多个标签，原串行查询平均响应 10 秒左右，高并发下数据库崩溃。

解决思路

  • 前置过滤 + 并行化 + 多级缓存
  • 布隆过滤器过滤无效主键 + Kafka 异步刷日志
  • 限流熔断保障系统稳定性

优化效果

10 秒左右 → 800ms

Kafka 异步解耦优化 11min → 15s

问题背景

每批 1000-3000 条，同步循环入库 + 多渠道通知，单批耗时 11-22 分钟。

解决思路

  • Kafka 拉取与消费分离，独立消费者组故障隔离
  • 指数退避重试 + 死信表人工补偿，全链路可追溯

优化效果

  • 定时任务：11 分钟 → 15 秒
  • 通知成功率：91% → 98%

Kafka 上游数据接入可靠性改造 丢失率 0.5% → 0

问题背景

上游系统通过 HTTP 接口推送预警数据，存在数据丢失、责任不清、人工成本高（月均 15+ 工单）三大问题。

解决思路

  • acks=all + 幂等生产者，失败表 + 指数退避重试
  • 手动提交 offset + Redis 幂等去重，约定「Kafka 为界」

优化效果

  • 丢失率 0.5% → 0，人工介入 15 次/月 → 0
  • 已推广至团队其他 3 个接入场景

老系统智能化升级 → 问答助手

问题背景

老系统需支持自然语言生成行为画像报告或查询表信息。

解决思路

  • Dify 工作流：意图识别 → Switch 路由 → 画像 / 查表 / 兜底
  • iframe 零侵入嵌入，配置化白名单 + 敏感字段脱敏

效果

  • 学习成本降低 80%，开发周期缩短 70%
